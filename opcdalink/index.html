OpcDaLink

OPC DA → OPC UA bridge

Sits in front of a legacy OPC DA server, connects to it as a client over DCOM, and re-publishes the whole address space as a modern OPC UA server, with history from OPC HDA and alarms from OPC AE alongside it. Point UaExpert, a new SCADA package, or HistorianLink at the UA endpoint and leave the old server exactly as it is.

Features

What it does.

OpcDaLink connects to the DA server as an ordinary client and never changes its configuration. Modern UA clients connect to OpcDaLink and never need to touch DCOM.

  • Full address-space mirror: branches become folders, leaves become variables, item IDs carry through as string NodeIds.
  • Faithful type mapping: canonical VARIANT types to UA variant types, DA quality words to UA status codes, item timestamps as source timestamps.
  • Read and write: access rights map to node writability, with writes passed back through to DA.
  • History over OPC UA: connect an OPC HDA server and UA clients read its history with standard HistoryRead, from a separate HDA folder in the address space.
  • Alarms: from OPC AE, an OPC UA server's alarms and conditions, or, through an optional agent, an OLE DB alarm archive, republished as UA nodes.
  • No Automation Wrapper: talks to the OPC DA custom interface directly, so there is no OPCDAAuto.dll to track down and register.
  • Big-server mode: feed it a tag list file and skip browsing entirely on servers with tens of thousands of items.
  • Built-in diagnostics: connection state and item count exposed as UA nodes, plus a web admin page.
Architecture

How it fits in.

OpcDaLink installs as two Windows services and a tray icon. The comms engine owns every live connection and keeps serving UA clients while the admin interface is restarted or upgraded.

Optional sources

More than live values.

Each optional source connects, reconnects and fails independently of OPC DA, and each publishes into its own folder. All are off by default.

SourcePublished asHow it works
OPC HDA historyAn HDA folder in the UA address spaceA UA client's HistoryRead is translated on demand into a raw read against the historian. OpcDaLink stores no history itself, so the answer includes data from before it was installed.
OPC AE alarmsOPC UA Alarms and ConditionsSubscribes to an OPC AE server and publishes its conditions, grouped by category, with ConditionRefresh and Acknowledge support.
OLE DB alarm archiveCurrent alarm state as UA nodesFor systems that keep their alarm archive in a database instead of serving it over OPC, such as classic WinCC. Uses the same small alarm agent as HistorianLink.
OPC UA alarmsUA nodes alongside the DA dataConnects to another OPC UA server as a standard Alarms and Conditions client and republishes its alarms.
Requirements

System requirements.

Operating system64-bit Windows 10 or 11, or Windows Server 2016 or later. Physical and virtual machines are both supported.
OPC DA serverAn OPC DA 2.0 server, local or remote, including DA 3.0 servers that also expose the DA 2.0 interfaces. 32-bit and 64-bit servers are both supported.
OPC prerequisitesThe OPC Foundation Core Components Redistributable is required for remote DA servers and recommended in all cases. The old Automation Wrapper (OPCDAAuto.dll) is not required.
RightsLocal administrator to install, upgrade or uninstall. DA, HDA and AE calls are made as one Windows account with DCOM rights on the DA server.
DiskAbout 150 MB for the program. Logs are capped at about 6 MB.
MemoryModest. The current value of every mirrored item is held in memory; the default cap is 50,000 items.
DatabaseNone. OpcDaLink is self-contained and does not store history locally.
InternetNot required at any point, including licensing.
Security

Built for plant networks.

01 / UNCHANGED

The DA server is left as it is

OpcDaLink needs only the access any DA client has. UA clients can write only to items the DA server already allows writes on.

02 / OPC UA

Sign, or sign and encrypt

Basic256Sha256 with messages signed, or signed and encrypted, which is the recommended mode for production. An unsecured mode exists for bench testing only.

03 / USERS

UA accounts with write control

UA users are separate from the admin account. Anonymous logins can be switched off, and each user is read-only unless explicitly allowed to write.

04 / ADMIN

Administration stays local

The admin interface listens on the loopback address only, which keeps the administration surface off the plant network.

05 / UPTIME

Two services

The comms engine keeps serving UA clients while the admin interface is restarted, upgraded or stopped.

06 / CONFIG

Encrypted at rest

Credentials and connection settings are encrypted with Windows DPAPI, tied to the machine. Nothing sensitive sits in plain text on disk.
