Features

What it does.

HistorianLink runs on a Windows machine that can reach your historian. Engineers and viewers use it from their own browsers, so there is no client software to roll out.

  • History export jobs: raw reads resampled to any interval, millisecond timestamps, plain-English quality column, UTC or local toggle, metadata header block.
  • Scheduled reports: repeatable report definitions written to .xlsx, last five runs kept per report.
  • Live dashboards: tiles with current value and sparkline, polled only while someone is watching.
  • Current alarms: live alarms read over OPC UA from the historian, or from a separate alarm server if you have one.
  • Alarm history (optional WinCC add-on): a satellite agent reads the WinCC message archive over OLE DB, the supported route when UA returns BadNotImplemented for event history.
  • Trend analyser: multi-tag chart with severity colouring, presets and a scrubbing ruler.
  • Three access levels: admin on loopback, engineer over TLS, read-only viewer.
  • Device trust: allow-list connections by IP, or IP + MAC with ARP verification.
  • Audit trail: logins, exports, config changes; no credentials, no stack traces.
Architecture

How it fits in.

One Windows service talks OPC UA to the historian and serves three separate web interfaces. Where WinCC alarm history is wanted, an optional agent on each OS server supplies it.

Requirements

System requirements.

Operating systemWindows Server 2016 or later, or Windows 10 or later, 64-bit. Physical or virtual.
RightsLocal administrator to install. The service then runs as LocalSystem.
Other softwareNone. HistorianLink is self-contained: no database server, no .NET or Python runtime, no internet access.
MemoryA host with 4 GB or more free is comfortable for typical use. Export jobs are built in memory, capped at 200 MB of held output.
DiskProgram files are small. Allow space for report outputs (the last five runs of each report) and the audit log.
ClockKeep the host clock synchronised (domain time or NTP). Certificate checks and scheduled reports depend on it.
BrowsersAny current Chromium-based browser, Firefox or Safari on engineer and viewer devices.
HistorianAny server that provides history over OPC UA, whatever the vendor.
Security

Built for plant networks.

01 / READ-ONLY

Never writes to the historian

HistorianLink connects as an OPC UA client and only browses tags and reads values and history. It never writes values or changes the historian's configuration.

02 / INTERFACES

Three separate interfaces

Admin, engineer and viewer each run on their own port. The admin page listens on loopback only and is never reachable on the engineer port.

03 / OPC UA

Signed and encrypted sessions

Basic256Sha256 with SignAndEncrypt by default, with Aes128_Sha256_RsaOaep and Aes256_Sha256_RsaPss also supported. The historian administrator trusts HistorianLink's certificate explicitly.

04 / TLS

HTTPS for network users

The engineer and viewer interfaces run over HTTPS with a minimum of TLS 1.2, enabled during commissioning.

05 / ACCESS

Roles and device trust

Administrator, engineer and viewer roles, with an optional allow-list of devices by IP, or by IP and MAC address on the same subnet.

06 / RECORDS

Audit trail and encrypted config

Logins, exports and configuration changes are logged. Credentials and connection settings are encrypted with Windows DPAPI, tied to the machine.
