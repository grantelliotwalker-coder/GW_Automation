HistorianLink

OPC UA history · reports · dashboards · alarms

Connects as an OPC UA client to a plant historian (Siemens Process Historian, WinCC, or any compliant UA server) and turns its archive into data you can work with. Browse the tag tree, pull raw history, resample it, and export to Excel or CSV with real quality codes attached.

Click the screenshot to enlarge
  • History export jobs: raw reads resampled to any interval, millisecond timestamps, plain-English quality column, UTC or local toggle, metadata header block.
  • Scheduled reports: repeatable report definitions written to .xlsx, last five runs kept per report.
  • Live dashboards: tiles with current value and sparkline, polled only while someone is watching.
  • Alarm history: a satellite agent reads the WinCC message archive over OLE DB, the supported route when UA returns BadNotImplemented for event history.
  • Trend analyser: multi-tag chart with severity colouring, presets and a scrubbing ruler.
  • Three access levels: admin on loopback, engineer over TLS, read-only viewer.
  • Device trust: allow-list connections by IP, or IP + MAC with ARP verification.
  • Audit trail: logins, exports, config changes; no credentials, no stack traces.

OpcDaLink

OPC DA → OPC UA bridge

Sits in front of a legacy OPC DA server, connects to it as a client over DCOM, and re-publishes the whole address space as a modern OPC UA server, with history from OPC HDA and alarms from OPC AE alongside it. Point UaExpert, a new SCADA package, or HistorianLink at the UA endpoint and leave the old server exactly as it is.

Click the screenshot to enlarge
  • Full address-space mirror: branches become folders, leaves become variables, item IDs carry through as string NodeIds.
  • Faithful type mapping: canonical VARIANT types to UA variant types, DA quality words to UA status codes, item timestamps as source timestamps.
  • Read and write: access rights map to node writability, with writes passed back through to DA.
  • History over OPC UA: connect an OPC HDA server and UA clients read its history with standard HistoryRead, from a separate HDA folder in the address space.
  • Alarms: from OPC AE, an OPC UA server's alarms and conditions, or the WinCC message archive through the OLE DB agent, republished as UA nodes.
  • No Automation Wrapper: talks to the OPC DA custom interface directly, so there is no OPCDAAuto.dll to track down and register.
  • Big-server mode: feed it a tag list file and skip browsing entirely on servers with tens of thousands of items.
  • Built-in diagnostics: connection state and item count exposed as UA nodes, plus a web admin page.

Shared platform

Both products are built the same way.

Same installer, same service model, same licensing, same security posture. Learn one, you know both.

01 / SERVICE

Windows service + tray

Runs headless as a service and survives reboots. A tray icon gives operators start, stop and status without opening the admin UI or needing a login.

02 / INTERFACE

Browser-based admin

No client to roll out. The service hosts its own UI on a local port. It's the same dark, dense, keyboard-friendly interface shown in the screenshots above.

03 / SECURITY

Encrypted config at rest

Credentials and connection settings are encrypted with Windows DPAPI, tied to the machine. Nothing sensitive sits in plain text on disk.

04 / NETWORK

TLS where it matters

Network-facing endpoints run HTTPS with a minimum of TLS 1.2. Admin access stays on loopback, so it is never exposed to the network.

05 / LICENSING

Fully offline activation

A digitally signed licence file for your site, checked on the machine. No activation server, no internet, no phone-home. Designed for air-gapped plant networks.

06 / DEPLOYMENT

Standard MSI install

A standard MSI your IT team can review, deploy and uninstall cleanly. Silent install supported for managed rollouts.

Questions

Frequently asked questions.

Does HistorianLink change anything on our historian?

No. HistorianLink is read-only: it connects as an OPC UA client and only reads tags and history. It never writes values or changes the historian's configuration.

Does OpcDaLink change our OPC DA server?

No. It connects as an ordinary OPC DA client and leaves the server's configuration exactly as it is. UA clients can only write to items the DA server already allows writes on.

Does it need internet access?

No. Licensing is checked on the machine itself, with no activation server and no phone-home, so both products run on fully air-gapped plant networks.

Where does it get installed?

On a Windows PC or server that can reach your historian or DA server: the historian machine itself, or a separate machine on the same network. It runs on Windows Server 2016+ and Windows 10+.

Can it run on a virtual machine?

Yes. Both products are supported on virtual machines, and most trials start on a spare one.

Which historians does HistorianLink work with?

Siemens Process Historian, WinCC, and any server that provides history over OPC UA. Alarm history from WinCC is read through a small satellite agent on the WinCC server.

How is it licensed?

One perpetual licence per site, with fully offline activation and no per-tag pricing: the price doesn't change with the size of your system. The licence isn't tied to one computer, so replacing or moving a server doesn't need a new one. Email us for a quote.

What happens after the 90-day trial?

You get a permanent licence for your site. Add it on the admin page and everything you set up during the trial carries straight over, with no reinstall. The software shows how many trial days are left, so it never stops by surprise.

Is there an installation manual?

Yes, a full installation and commissioning manual for each product, covering planning, firewall rules, security hardening, upgrades and troubleshooting. It's sent with every trial, or email to request a copy for your IT or security team to review first.

How do updates work?

A new version is a new installer run over the top of the old one. Your configuration, licence and reports are kept.
